# テスト計画 (Test Plan) — QR コード LAN データ転送(QRDrop)

## 1. テスト環境

- 環境: Windows 11 Home(10.0.26200)、Go 1.26.1、LAN IP 192.168.1.3(Wi-Fi)。
  スマホ実機(iOS Safari / Android Chrome)は本環境に**存在しない**。
  スマホ操作は HTTP レベルの同等リクエスト+QR デコード検証で代替し、
  実機確認は既知の制約として test-report.md に記録する。
- 自動テスト実行コマンド:
  - 単体: `cd 04-qr-lan-transfer/qrdrop && go test ./cmd/... ./internal/...`
  - E2E(実バイナリ起動): `cd 04-qr-lan-transfer/qrdrop && go test ./e2e/ -v`(内部で `go build` し実プロセスを起動する)
- テストデータ: E2E テストが一時フォルダに自動生成(100MB ファイル含む)

## 3. テストケース詳細

### TC-001: 起動と管理ページ・QR 表示(REQ-001 受け入れ基準1)

- **前提 (Given)**: LAN 接続済みの PC、ビルド済み qrdrop.exe
- **操作 (When)**: `-no-browser` で起動し、`http://127.0.0.1:<port>/admin` と `/admin/qr.png` を GET
- **期待結果 (Then)**: 200 + 管理ページ HTML(「QRDrop 管理ページ」を含む)、qr.png が PNG マジックバイトで始まる

### TC-002: QR デコード → 転送ページ(REQ-001 受け入れ基準2 の実機代替)

- **前提 (Given)**: TC-001 の起動済みサーバ
- **操作 (When)**: `/admin/qr.png` を QR デコーダ(gozxing)でデコードし、得られた URL を LAN IP 経由で GET
- **期待結果 (Then)**: デコード結果が `http://<LAN-IP>:<port>/s/<token>` 形式で `/admin/info` の URL と一致し、GET が 200 + 転送ページ HTML

### TC-003: LAN 未接続エラー(REQ-001 受け入れ基準3)

- **前提 (Given)**: プライベート IPv4 が 1 件も検出されない状態(単体テストで注入)
- **操作 (When)**: 起動時チェック関数を空の IP リストで呼ぶ
- **期待結果 (Then)**: 「ネットワーク未接続」を含むエラーが返り、起動が中断される
- **備考**: 物理的な LAN 切断での実機確認は環境制約により未実施(既知の制約)

### TC-004: ファイル送信(REQ-002 受け入れ基準1)

- **前提 (Given)**: 起動済みサーバ、有効トークン
- **操作 (When)**: LAN IP 経由で `POST /s/<token>/upload`(multipart、file パート)
- **期待結果 (Then)**: 200、受信フォルダにファイルが保存され内容一致、`/admin/items` の received に項目が現れる

### TC-005: テキスト送信(REQ-002 受け入れ基準2)

- **操作 (When)**: `POST /s/<token>/text` でテキスト送信後、`/admin/items` を GET
- **期待結果 (Then)**: received にテキスト項目があり全文一致(コピー動作はブラウザ機能のため TC-013 と同じく実機外)

### TC-006: 同名連番(REQ-002 受け入れ基準3)

- **操作 (When)**: 同名ファイルを 2 回アップロード
- **期待結果 (Then)**: `name.ext` と `name (1).ext` の両方が存在し、上書きされない

### TC-007: PC → スマホ共有(REQ-003 受け入れ基準1・2)

- **操作 (When)**: SSE(`/s/<token>/events`)を購読した状態で `POST /admin/share`(ファイル+テキスト)し、通知受信後 `/s/<token>/items` → `/s/<token>/files/<id>` を GET
- **期待結果 (Then)**: SSE 通知が5秒以内に届き、items にファイルとテキスト(全文)が現れ、ダウンロード内容が元ファイルと一致

### TC-008: LAN 外アクセス遮断(REQ-004 受け入れ基準1)

- **前提 (Given)**: モバイル回線からの実アクセスは再現不能のため、RemoteAddr をパブリック IP(203.0.113.7)に偽装した統合テストで代替
- **操作 (When)**: 有効トークンの URL へ偽装リクエスト
- **期待結果 (Then)**: 403(guard 単体テスト TestMiddlewarePublicIPBlocked + web 統合テストで検証)

### TC-009: 外部通信ゼロ(REQ-004 受け入れ基準2)

- **前提 (Given)**: E2E テスト実行中の qrdrop プロセス
- **操作 (When)**: 転送実行直後に `Get-NetTCPConnection -OwningProcess <pid>` で当該プロセスの TCP 接続を列挙
- **期待結果 (Then)**: リモートアドレスがすべてループバックまたは LAN 内プライベート IP であり、外部宛て接続が存在しない

### TC-010: トークンなし拒否(REQ-004 受け入れ基準3)

- **操作 (When)**: LAN IP 経由で `/` と `/s/`(空トークン)を GET
- **期待結果 (Then)**: いずれも 403。`127.0.0.1` からの `/admin` は 200(除外規定)

### TC-011: TTL 失効(REQ-005 受け入れ基準1)

- **前提 (Given)**: `-ttl 2s` で起動した専用インスタンス
- **操作 (When)**: 3 秒待機後に転送ページ URL を GET
- **期待結果 (Then)**: 403 + 「読み取り直してください」を含む案内(30 分の既定値は session 単体テストで境界検証済み)

### TC-012: 手動失効・再発行(REQ-005 受け入れ基準2)

- **操作 (When)**: `POST /admin/session/revoke` 後、旧 URL と新 URL(/admin/info から取得)を GET
- **期待結果 (Then)**: 旧 URL 403、新 URL 200、QR PNG が新 URL を指す(デコードで確認)

### TC-013: 進捗表示(REQ-006・Could)

- **操作 (When)**: スマホブラウザで 100MB ファイルを送信し進捗バーを目視
- **期待結果 (Then)**: 進捗率が表示される
- **備考**: ブラウザ実機がなく未実施。Could 要件のため既知の制約として記録

### TC-014: 性能・サイズ上限(NFR-001)

- **操作 (When)**: 100MB のランダムファイルを LAN IP 経由でアップロードし所要時間を計測。サイズ上限超過は transfer 単体テスト(413)で検証
- **期待結果 (Then)**: 30 秒以内に完了(ローカルホスト内計測。実 Wi-Fi の帯域差は既知の制約として記録)

### TC-015: パストラバーサル防止(NFR-002)

- **操作 (When)**: ファイル名 `..\..\evil.txt` を E2E でアップロード
- **期待結果 (Then)**: 受信フォルダ内に `evil.txt` として保存され、フォルダ外に書かれない(guard/transfer 単体テストの 13 パターンと併用)

### TC-016: 非永続化(NFR-005)

- **操作 (When)**: 共有・受信を行った後プロセスを終了し、再起動して `/admin/items` を GET
- **期待結果 (Then)**: received / shared とも空。受信フォルダのファイル本体は残っている

### TC-017: ログ方針(NFR-004)

- **操作 (When)**: 一意のマーカー文字列をテキスト送信し、`%APPDATA%\QRDrop\logs\` の当日ログを検索
- **期待結果 (Then)**: `op=upload` 等の操作記録が存在し、マーカー文字列(本文)がログに含まれない
