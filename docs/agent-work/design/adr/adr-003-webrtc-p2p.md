# ADR-003: v2 のデータ転送方式は「WebRTC DataChannel P2P(host candidate 限定)+ Cloudflare 経由のシグナリング」とする

- **日付**: 2026-07-13
- **状態**: 提案(G2 承認待ち)
- **決定者**: Architect(Claude Code)

## 文脈 (Context)

v2(Web 版)では、サイト自体はインターネット上(Cloudflare)で公開しつつ、
ファイル・テキスト本文は同一ネットワーク限定を維持する必要がある(REQ-101〜106、
特に REQ-104。DEC-010)。v1 のような「PC 上のローカルサーバに直接繋ぐ」方式は
使えない(公開サーバは利用者の LAN 内に存在しないため)ため、
公開サイトとデータ転送経路をどう分離するかを決める。

なお「LAN 限定を外して任意の2者間で使えるようにするか」をユーザーに確認したが、
現行の LAN 限定を維持する方針が確定している(state.md 作業ログ 2026-07-13 参照)。

## 検討した選択肢

### 案A: WebRTC DataChannel P2P(STUN/TURN 不使用・host candidate 限定)+ Cloudflare Worker/Durable Object によるシグナリング — 採用

- 利点: ファイル本体・テキスト本文は PC・スマホ間で直接転送され、Cloudflare を一切経由しない(REQ-104 を構造で満たす)。STUN/TURN を使わないため、接続候補が端末自身のローカル IP(host candidate)のみとなり、同一 LAN 外では物理的に接続が成立しない。WebRTC 仕様により DataChannel は DTLS で自動暗号化される(証明書警告なし)。TURN 不使用のため中継の帯域費用が発生しない
- 欠点: シグナリングサーバ(ルーム管理・SDP/ICE 交換)の実装が新たに必要。WebRTC 特有の実装複雑さ(ICE 候補収集、SDP 交換の手順管理)がある。ブラウザ・OS の組み合わせによりまれに接続確立に失敗する場合がある(P4 で実機検証)

### 案B: Cloudflare Worker が全データを中継する単純 HTTP リレー — 却下

- 利点: v1 のローカル HTTP サーバをそのままクラウド上に持ち上げる発想で実装が単純
- 欠点: ファイル本体・テキスト本文が Cloudflare Worker を経由するため「同一ネットワーク限定」の Must 要件(REQ-104)に構造的に違反する。Workers Free の 1 日 10 万リクエスト・1 リクエストあたり CPU 時間 10ms という制限にも転送量次第で抵触しやすい
- 却下理由: REQ-104(Must)に真っ向から反するため採用不可

### 案C: WebRTC + STUN/TURN 併用(一般的な P2P 構成) — 却下

- 利点: NAT 越えの成功率が高く、異なるネットワーク間でも接続できる
- 欠点: STUN 利用で自端末のグローバル IP が外部(STUN サーバ)に伝わる。TURN を有効にすると LAN 外への中継転送も可能になってしまい、同一ネットワーク限定が構造的に崩れる。TURN の運用は Cloudflare の完全無料枠に含まれない(Cloudflare Realtime TURN は従量課金)
- 却下理由: REQ-104 に反し、かつユーザーが確認済みの「LAN 限定を維持する」方針(state.md 2026-07-13)に反する

## 決定 (Decision)

案A を採用する。「同一ネットワーク限定」という Must 要件を、後付けの検査ロジックではなく
STUN/TURN 不使用という**接続方式そのもの**で構造的に満たせる点が決め手。
Cloudflare が扱うのはルーム作成・SDP/ICE 交換等の制御メタデータのみであり、
これは v1 における「LAN 内 HTTP 直結」の設計思想(adr-001)を Web 版向けに踏襲したもの。

## 影響 (Consequences)

- シグナリングプロトコル(ルーム作成・参加・SDP/ICE 中継・失効)の設計・実装が新規に必要(design-doc.md v2 で詳細化)
- AP アイソレーション有効なルーターでは v1 同様に接続できない(既知の制約として README に明記)
- ブラウザの WebRTC 実装差により、まれに接続確立に失敗するケースがある(P4 で複数ブラウザの実機検証を行い、失敗時のエラー表示を用意する)
- 費用: なし(STUN/TURN 未使用のため、Cloudflare の課金要素になりうる中継帯域が発生しない)
