# ADR-002: 通信保護は「HTTP 平文 + ワンタイムトークン + プライベート IP 検査」とする

- **日付**: 2026-07-09
- **状態**: 提案(G2 承認待ち)
- **決定者**: Architect(Claude Code)

## 文脈 (Context)

LAN 内の HTTP 通信をどう保護するか(REQ-004, REQ-005, NFR-002)。
ローカル IP に対する正規の TLS 証明書は取得できないため、HTTPS を使うなら
自己署名証明書になるが、スマホブラウザでは強い警告が出る。

## 検討した選択肢

### 案A: HTTP 平文 + ワンタイムトークン(TTL 30分)+ プライベート IP 検査 — 採用

- 利点: QR を読むだけで警告なく開ける(中核体験を維持)、実装が単純で攻撃面が小さい
- 欠点: 同一 LAN 内に攻撃者がいる場合、通信の盗聴・改ざんが可能

### 案B: 自己署名証明書による HTTPS — 却下

- 利点: LAN 内盗聴に耐える
- 欠点: iOS Safari / Android Chrome で「安全でない接続」警告が出て、ユーザーが毎回手動で例外承認する必要がある(iOS はプロファイル導入までしないと恒久解除できない)
- 却下理由: 「QR を読むだけで使える」という成功基準(30秒以内に転送開始)を満たせない

### 案C: mkcert 等でローカル CA を作りスマホに CA 証明書を導入 — 却下

- 利点: 警告なしの HTTPS が成立
- 欠点: スマホへの CA 導入はアプリ導入より重い手順で、セキュリティ上も CA 私有鍵の管理リスクを新設する
- 却下理由: 手軽さの要求と根本的に相反する

## 決定 (Decision)

案A を採用する。想定利用環境(自宅の WPA2/WPA3 保護された Wi-Fi)では
無線区間は暗号化されており、残る脅威「同一 LAN 内の悪意ある同居デバイス」は
家庭内個人利用では受容可能と判断した。トークン+IP 検査+TTL で
「LAN 外」「QR を知らない者」「期限切れ」からのアクセスは遮断される。

## 影響 (Consequences)

- 公衆 Wi-Fi・共有オフィス LAN での利用は非推奨(README に明記する)
- 機密性の高いファイルの転送には向かない旨を利用者向け文書に記載
- 要件が変わった場合(信頼できない LAN での利用が必要になった場合)は本 ADR を置換し案C を再検討
- 費用: なし
