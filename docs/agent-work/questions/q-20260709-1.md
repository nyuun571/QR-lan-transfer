# 質問票 q-20260709-1 — QR コード LAN データ転送

- **日付**: 2026-07-09 / **分類**: CLARIFY(G1/G2 でまとめて提示)
- **状態**: 未回答(前提を置いて作業継続中。前提は decision-log.md 参照)

## Q1: 「Webサイト上にQRコード表示」の解釈

「PC 上で動くローカルサーバが自分の管理ページ(Web ページ)に QR を表示する」と解釈した。
インターネット上に公開された Web サイトを指す場合は、LAN 限定要求と両立させる別設計
(公開サイトは QR 生成のみ・転送は LAN 内)が必要になる。

- 案A(推奨): ローカルサーバの管理ページに QR 表示。理由: 外部依存ゼロで「同一ネットワーク限定」と完全に整合
- 案B: 公開 Web サイトで QR 生成のみ行い、転送は LAN 内(サイト運用が必要になり複雑化)
- **置いた前提**: 案A

## Q2: LAN 内通信の暗号化

HTTP 平文 + トークン + IP 検査とし、HTTPS(自己署名)は不採用とした(ADR-002)。
同一 LAN 内に信頼できないデバイスがいる環境では盗聴されうる。

- 案A(推奨): HTTP 平文。理由: QR を読むだけで警告なく使える体験を優先。自宅 Wi-Fi 前提
- 案B: 自己署名 HTTPS(スマホで毎回警告の手動承認が必要)
- **置いた前提**: 案A(DEC-005)

## Q3: 受信ファイルの保存先

PC 側の保存先を `ダウンロード\QRDrop\` 既定(設定で変更可)とした。

- 案A(推奨): 上記既定+設定変更可
- 案B: 毎回ダイアログで選択(転送のたびに操作が増える)
- **置いた前提**: 案A
