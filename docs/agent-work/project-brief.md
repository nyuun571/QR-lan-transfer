# 企画書 (Project Brief) — QR コード LAN データ転送

## 1. 背景・課題 (Why)

スマホと PC の間でファイルやテキストをちょっと移したいとき、クラウド(Drive・LINE 等)を
経由するのは大げさで、プライバシー面でも外部サーバに預けたくない。USB ケーブルや
専用アプリのセットアップも面倒。同一 Wi-Fi にいるのだから、その場で直接渡したい。

> 初期要求(原文): 「Webサイト上にQRコード表示することで、スマホとPC間でのデータ転送を
> 行うような環境を実現したい。データの転送は、同一ネットワークに接続している機器内でしか
> 行われないようにする。」

## 2. 想定ユーザーと利用場面 (Who / When)

- 主ユーザー: 本人(PC: Windows 11、スマホ: 一般的なモバイルブラウザ搭載機)【仮説】
- 利用場面: 自宅等の同一 Wi-Fi 内で、写真・ファイル・URL・テキストを PC⇔スマホで受け渡すとき
- 想定規模: 個人利用、同時セッション1〜2件【仮説】

## 3. 作るものの概要 (What)

PC 上で起動するローカル Web サーバアプリ。起動すると PC のブラウザに管理ページが開き、
LAN 内アドレス+ワンタイムトークンを埋め込んだ URL の QR コードを表示する。
スマホのカメラで QR を読むとスマホのブラウザで転送ページが開き、アプリ不要で
ファイル・テキストの送受信(スマホ→PC アップロード、PC→スマホ ダウンロード)ができる。
サーバはプライベートネットワークからの接続のみ受け付け、インターネットには一切公開しない。【仮説】

## 4. スコープ仮説

### やること

- QR コードによる接続(URL + ワンタイムトークン)
- スマホ → PC のファイル/テキスト送信
- PC → スマホ のファイル/テキスト送信
- 同一 LAN(プライベートアドレス)以外からの接続拒否
- セッションの失効(TTL・手動終了)

### やらないこと

- インターネット越しの転送・クラウド中継(要求の「同一ネットワーク限定」に反するため)
- スマホ専用アプリの開発(ブラウザのみで完結させる)
- 転送履歴の永続化・同期
- PC⇔PC、スマホ⇔スマホ間の転送(初版対象外)【仮説】

## 5. 成功基準

- PC でアプリを起動し、スマホで QR を読んでから 30 秒以内に写真1枚を PC に送れる
- PC に置いたファイルをスマホからダウンロードできる
- LAN 外(モバイル回線など)から同じ URL にアクセスしても接続できない

## 6. 制約

| 種類 | 内容 |
|------|------|
| 期限 | 指定なし |
| 技術指定 | 指定なし(Web サイト上の QR 表示、LAN 限定は必須要求) |
| 予算・費用 | 無料の範囲(外部サービス・サーバを使わない) |
| 既存システム | 家庭内 Wi-Fi ルーター(AP アイソレーションが無効であること) |

## 7. リスク・懸念(この時点で見えているもの)

- Wi-Fi ルーターの AP アイソレーション(クライアント間分離)が有効だと通信できない(環境依存)
- LAN 内は HTTP 平文となる想定 → 同一 LAN 内の盗聴リスクをどこまで許容するか(要件で判断)
- Windows ファイアウォールの受信許可が初回に必要(セットアップ手順に明記が必要)
- スマホブラウザの制約(大容量アップロードの安定性)
