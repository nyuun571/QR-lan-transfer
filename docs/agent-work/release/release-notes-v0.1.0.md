## 実装機能

| 要件 | 内容 |
|------|------|
| REQ-001 | 起動するだけで LAN IP 自動検出・空きポート確保・管理ページに接続用 QR コードを表示(複数 NIC は管理ページで選択可、LAN 未接続はエラー) |
| REQ-002 | スマホ→PC のファイル(複数可)・テキスト転送。`ダウンロード\QRDrop\` へ保存、同名は連番、テキストはワンクリックコピー |
| REQ-003 | PC→スマホのファイル・テキスト共有。SSE によりスマホ側一覧へ即時反映、タップでダウンロード/コピー |
| REQ-004 | 同一ネットワーク限定通信(外部サーバ不使用・プライベート IP 検査・トークンなし 403・ポート開放なし)。転送中の外部通信ゼロを実測確認 |
| REQ-005 | セッション失効(TTL 既定 30 分+管理ページから即時失効・QR 再発行)。失効後は再読取案内 |
| REQ-006 | 複数ファイル一括アップロード・XHR 進捗バー(進捗 UI の実機目視は未実施 → 既知の問題) |

非機能: 100MB 転送 0.88 秒実測(NFR-001)/ 128bit 暗号乱数トークン・パストラバーサル防止・2GB 上限(NFR-002)/ 本文非記録のローカルログ(NFR-004)/ 一覧はメモリ保持のみ(NFR-005)

## 既知の問題

> test-report.md から転記。Must 要件の未達をここに含めることはできない。

| 内容 | 影響 | 回避策 |
|------|------|--------|
| TC-013: スマホ実機での進捗バー目視確認が未実施(Could 要件。環境にスマホ実機なし) | 進捗表示 UI の見た目が実機未確認(転送・保存機能自体は検証済み) | 初回利用時に確認。問題があれば P7 の変更要求として受付 |

| レビュー Minor #2〜#4(同時同名アップロードの稀な 500 / admin POST の CSRF なし / DEC-004 のサブネット検査文言差) | 個人利用・同一 LAN の受容済み脅威モデルでは低リスク(review-report-1.md 参照) | 対応は任意。必要なら変更要求として受付 |

## セットアップ / アップグレード手順

```
winget install GoLang.Go
cd 04-qr-lan-transfer/qrdrop
set GOTOOLCHAIN=go1.26.5   # レビュー指摘 #1 対応(stdlib 脆弱性パッチ済み toolchain)
go build ./cmd/qrdrop
.\qrdrop.exe
# 初回起動時の Windows ファイアウォールダイアログは「プライベートネットワーク」のみ許可
```

アップグレード/ロールバック: exe の差し替えのみ(永続データは受信ファイルだけで互換性問題なし)。
