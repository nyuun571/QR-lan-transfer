### DEC-005: LAN 内通信は HTTP(平文)+ ワンタイムトークンとし、HTTPS は採用しない

- **日付**: 2026-07-09 / **工程**: P2 / **種別**: 判断
- **内容**: 自己署名証明書による HTTPS は採用せず、HTTP + セッショントークン + プライベート IP 検査で保護する([adr-002](design/adr/adr-002-transport-security.md))。
- **理由**: 自己署名証明書はスマホブラウザで警告・接続拒否となり「QR を読むだけで使える」という中核体験を壊すため。脅威(同一 LAN 内の盗聴)は家庭内利用では限定的。
- **影響**: 公衆 Wi-Fi など信頼できない LAN での利用は非推奨(README に明記)。要件が変われば mkcert 等の導入を再検討。
- **人間への開示**: 未(G2 で提示。質問票 Q2)

### DEC-004: 「同一ネットワーク限定」の実現方式は「プライベート IP 検査 + 外部公開しない」の多層防御とする

- **日付**: 2026-07-09 / **工程**: P1 / **種別**: 判断
- **内容**: (1) サーバは LAN インターフェースにバインド、(2) 接続元 IP が RFC1918 プライベート範囲かつサーバと同一サブネットであることを検査、(3) UPnP 等のポート開放は行わない、(4) トークンなしのアクセスは拒否、の4層で「同一ネットワーク内のみ」を担保する。
- **理由**: 単一の対策では設定ミスや環境差で破れうるため。
- **影響**: VPN 経由や複数サブネット構成の LAN では接続できない場合がある(仕様として明記)。
- **人間への開示**: 未(G1 で提示)

### DEC-003: スマホ側はブラウザのみで完結させる(アプリ・PWA 化しない)

- **日付**: 2026-07-09 / **工程**: P0 / **種別**: 前提
- **内容**: スマホ側は QR で開く Web ページのみとし、ネイティブアプリや PWA インストールは作らない。
- **理由**: 「QR を読むだけで使える」手軽さが本企画の価値であり、アプリ配布はその価値を損なうため。
- **影響**: ブラウザ API の制約(バックグラウンド転送不可等)を受け入れる。
- **人間への開示**: 未(G1 で提示)

### DEC-002: PC 側の対象は Windows 11、スマホ側は現行の iOS Safari / Android Chrome とする

- **日付**: 2026-07-09 / **工程**: P0 / **種別**: 前提
- **内容**: サーバアプリは Windows 11 で動作確認。スマホ側は現行メジャーブラウザ(iOS Safari、Android Chrome)を対象とする。
- **理由**: 依頼者の環境が Windows 11。スマホ機種は不明のため両 OS の標準ブラウザを対象に置いた。
- **影響**: 技術選定はクロスコンパイル可能なものを選ぶ(将来の macOS/Linux 対応余地)。
- **人間への開示**: 未(G1 で提示)

### DEC-001: ユーザー指示により P0〜P2 を一括実施し、G1/G2 承認をまとめて依頼する

- **日付**: 2026-07-09 / **工程**: P0 / **種別**: 判断
- **内容**: 人間から「idealist.md の各アイディアに対する設計まで行う」旨の一括指示を受けたため、要件定義書・設計書をドラフトとして先行作成し、G1・G2 の承認依頼を最終報告でまとめて提示する。state.md 上は P1/P2 とも `WAITING_APPROVAL` とする。
- **理由**: 逐次ゲートで停止するとユーザーの一括指示(非同期実行)を満たせないため。
- **影響**: G1 で要件に修正が入った場合、P2 成果物は REWORK になる。
- **人間への開示**: 未(G1/G2 で提示)
