### DEC-008: Git タグは `qrdrop-v0.1.0`(接頭辞付き)とし、リリースビルドは go1.26.5 toolchain を用いる

- **日付**: 2026-07-12 / **工程**: P6 / **種別**: 判断
- **内容**: (1) 手順書のタグ形式は `v<semver>` だが、本リポジトリは複数プロジェクト(01〜04)が同居するため、曖昧さ回避としてプロジェクト接頭辞付きの `qrdrop-v0.1.0` とする。(2) レビュー指摘 #1(ビルド toolchain の stdlib 脆弱性)への対応として、リリースビルドは `GOTOOLCHAIN=go1.26.5` で行う(コード変更なし。govulncheck で 0 件を確認済み)。
- **理由**: (1) 単一リポジトリに複数プロジェクトのタグが混在すると `v0.1.0` がどのプロジェクトか判別できない。(2) 指摘 #1 の推奨対応そのもの。
- **影響**: 以後の本プロジェクトのタグはすべて `qrdrop-v<semver>` 形式。README のビルド手順に GOTOOLCHAIN 指定を反映済み(リリースノート参照)。
- **人間への開示**: G3 承認依頼で提示

### DEC-007: 実装時の設計補完(管理ページ用 API 3件の追加・共有ファイルのステージング保存・CLI フラグ)

- **日付**: 2026-07-12 / **工程**: P3 / **種別**: FYI(設計の詳細化。承認済み要件・設計の変更なし)
- **内容**: (1) design-doc §5 の API 一覧に加えて `GET /admin/info`(QR URL・NIC 一覧)、`POST /admin/interface`(NIC 選択。DES-001 の「管理ページで選択」の実現手段)、`GET /admin/items`(受信/共有一覧 JSON)を追加した。いずれも LanGuard によりループバック限定。(2) ブラウザからは実ファイルパスを取得できないため、PC 側共有ファイルは受信フォルダ配下のステージングフォルダ(`.qrdrop-share`、起動時に削除)へ保存し、そこを配信元とした(SharedItem.path は引き続き PC ローカル絶対パス)。(3) 検証・利便性のため CLI フラグ `-port / -dir / -ttl / -no-browser` を追加した(既定値は要件どおり)。
- **理由**: いずれも設計の意図(DES-001/003/005)を実現するための詳細であり、外部仕様・セキュリティ境界を変えないため差し戻し不要と判断。
- **影響**: design-doc の API 一覧と §4 データモデルの記述粒度と実装に差分がある(P5 レビューで整合を検査)。
- **人間への開示**: P5 完了報告で提示

### DEC-005: LAN 内通信は HTTP(平文)+ ワンタイムトークンとし、HTTPS は採用しない

- **日付**: 2026-07-09 / **工程**: P2 / **種別**: 判断
- **内容**: 自己署名証明書による HTTPS は採用せず、HTTP + セッショントークン + プライベート IP 検査で保護する([adr-002](design/adr/adr-002-transport-security.md))。
- **理由**: 自己署名証明書はスマホブラウザで警告・接続拒否となり「QR を読むだけで使える」という中核体験を壊すため。脅威(同一 LAN 内の盗聴)は家庭内利用では限定的。
- **影響**: 公衆 Wi-Fi など信頼できない LAN での利用は非推奨(README に明記)。要件が変われば mkcert 等の導入を再検討。
- **人間への開示**: 未(G2 で提示。質問票 Q2)

### DEC-004: 「同一ネットワーク限定」の実現方式は「プライベート IP 検査 + 外部公開しない」の多層防御とする

- **日付**: 2026-07-09 / **工程**: P1 / **種別**: 判断
- **内容**: (1) サーバは LAN インターフェースにバインド、(2) 接続元 IP が RFC1918 プライベート範囲かつサーバと同一サブネットであることを検査、(3) UPnP 等のポート開放は行わない、(4) トークンなしのアクセスは拒否、の4層で「同一ネットワーク内のみ」を担保する。
- **理由**: 単一の対策では設定ミスや環境差で破れうるため。
- **影響**: VPN 経由や複数サブネット構成の LAN では接続できない場合がある(仕様として明記)。
- **人間への開示**: 未(G1 で提示)

### DEC-003: スマホ側はブラウザのみで完結させる(アプリ・PWA 化しない)

- **日付**: 2026-07-09 / **工程**: P0 / **種別**: 前提
- **内容**: スマホ側は QR で開く Web ページのみとし、ネイティブアプリや PWA インストールは作らない。
- **理由**: 「QR を読むだけで使える」手軽さが本企画の価値であり、アプリ配布はその価値を損なうため。
- **影響**: ブラウザ API の制約(バックグラウンド転送不可等)を受け入れる。
- **人間への開示**: 未(G1 で提示)
